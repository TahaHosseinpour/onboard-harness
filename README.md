## Onboard Harness چیست؟

یک پوشه روی سیستم خود انتخاب می‌کنید و همان می‌شود «فضای کاری». ایجنت‌ها داخل همین پوشه فایل می‌خوانند و می‌سازند، جدول‌ها را جمع‌بندی می‌کنند و گزارش می‌نویسند. هر تغییری در فایل‌ها یا اجرای هر فرمان، اول به صندوق تأیید شما می‌رسد.

مثل یک مخزن (repository) است: هر فضای کاری یک پوشه است، همه‌چیز همان‌جا ذخیره می‌شود و پوشهٔ آن بعد از ساخت قابل تغییر نیست.

## فیچرها

همهٔ صفحه‌ها به موتور واقعی وصل‌اند؛ هیچ دادهٔ نمونه‌ای در برنامه نیست. هر چه می‌بینید از پوشهٔ فضای کاری خودتان می‌آید.

### کارها: گفتگو با ایجنت

کار را به زبان ساده بنویسید. هر کار یک گفتگوی زنده است:

- برنامهٔ چندمرحله‌ای ایجنت و پیشرفت هر مرحله را می‌بینید.
- هر اقدام ایجنت (خواندن فایل، محاسبه، نوشتن فایل، اجرای فرمان) یک خط ساده در گفتگو است.
- وسط کار می‌توانید پیام بدهید یا کار را متوقف کنید.
- فایل‌هایی که در این کار ساخته یا عوض شده‌اند کنار گفتگو فهرست می‌شوند.
- مدل، ایجنت و سطح اختیار («با تأیید»، «خودکار»، «فقط خواندن») را برای هر گفتگو جدا انتخاب می‌کنید.
- مصرف توکن و هزینهٔ هر کار نمایش داده می‌شود.

### صندوق تأیید

در حالت «با تأیید»، ایجنت قبل از تغییر فایل یا اجرای فرمان می‌ایستد و منتظر شما می‌ماند. برای هر اقدام می‌بینید دقیقاً چه چیزی قرار است انجام شود و می‌توانید تأیید کنید، ورودی‌اش را ویرایش کنید یا با ذکر دلیل رد کنید. کار بعد از تصمیم شما از همان‌جا ادامه پیدا می‌کند.

### فایل‌ها

مرورگر فایل‌های همان پوشهٔ فضای کاری:

- فایل‌های معمولی به‌صورت پیش‌فرض نمایش داده می‌شوند.
- فایل‌های سیستمی (ایجنت، مهارت، قانون، حافظه و سابقهٔ اجراها در `.harness/`) با فیلتر «فایل‌های سیستمی» دیده می‌شوند، با رنگ و آیکن جدا.
- فایل‌های متنی داخل خود برنامه باز و ویرایش می‌شوند؛ بقیه با برنامهٔ پیش‌فرض سیستم باز می‌شوند.

### سفارشی‌سازی

- **مهارت‌ها:** روش‌های کاری که ایجنت فقط وقتی لازم شد سراغشان می‌رود.
- **ایجنت‌ها:** دستیارهای تخصصی با دستورالعمل و ابزارهای خودشان.
- **قوانین و مجوزها:** برای هر پوشه و هر ابزار مشخص می‌کنید «مجاز» است، «با تأیید» یا «ممنوع».
- **حافظه:** چیزهایی که ایجنت باید در همهٔ کارها بداند.

### تنظیمات

تم روشن یا تیره، مدل‌ها و فضای کاری.

**مدل‌ها را خودتان تعریف می‌کنید:** نشانی پایه، کلید API و نام مدل (هر سرویس سازگار با OpenAI یا Anthropic). کلیدها در مخزن امن سیستم‌عامل نگه‌داری می‌شوند، نه در پوشهٔ فضای کاری. یک «مدل نمایشی» هم از اول هست که بدون کلید و اینترنت کار می‌کند و فقط برای دیدن روند برنامه است.

### هنوز ساخته نشده

داشبوردها و اهداف، نمودار تیم، اتصال به سرویس‌های بیرونی و اتوماسیون‌ها در طرح اولیه بودند ولی موتورشان هنوز نوشته نشده، برای همین از برنامه برداشته شده‌اند تا چیزی غیرواقعی نمایش داده نشود.

## ایمنی و کنترل

- ایجنت فقط داخل پوشهٔ فضای کاری کار می‌کند.
- مجوز هر ابزار «مجاز»، «با تأیید» یا «ممنوع» است.
- سقف تلاش، زمان و هزینه برای هر کار؛ ایجنت از آن عبور نمی‌کند.
- هر گام در یک فایل رویداد ثبت می‌شود تا بعداً قابل بازبینی باشد.
- کار نیمه‌تمام بعد از قطع شدن، از همان‌جا ادامه پیدا می‌کند.
- فرمان‌ها روی سیستم خودتان اجرا می‌شوند، با ایزوله‌سازی سبک.

## دانلود

آخرین نسخه برای ویندوز در صفحهٔ [Releases](https://github.com/TahaHosseinpour/onboard-harness/releases/latest) است:

- `Onboard-Harness-Setup-0.2.0.exe` — نصب‌کننده
- `Onboard-Harness-0.2.0-win-x64.zip` — نسخهٔ بدون نصب؛ از حالت فشرده خارج کنید و `Onboard Harness.exe` را اجرا کنید

موتور برنامه داخل همین بسته است؛ نصب Python یا چیز دیگری لازم نیست. بار اول یک پوشه برای فضای کاری انتخاب می‌کنید و بعد در «تنظیمات ← مدل‌ها» مدل خودتان را اضافه می‌کنید.

برنامه امضای دیجیتال ندارد، برای همین ویندوز بار اول هشدار SmartScreen نشان می‌دهد («More info» و بعد «Run anyway»).

## تست پذیرش

بک‌اند با یک فهرست ۶۶ موردی (حلقهٔ اجرا، مجوزها، حافظه، مهارت‌ها، پایداری، هزینه و …) با مدل واقعی سنجیده شده است. گزارش کامل در [backend/evals/REPORT.md](backend/evals/REPORT.md) و نتیجهٔ اجرای دوبارهٔ موارد ردشده با مدل‌های DeepSeek در [REPORT.deepseek-retest.md](backend/evals/REPORT.deepseek-retest.md) و [REPORT.deepseek41-retest.md](backend/evals/REPORT.deepseek41-retest.md) است. برای اجرای دوباره:

```bash
cd backend
set HARNESS_EVAL_KEY=کلید-شما
.venv\Scripts\python -m evals.run
```

## اجرا از روی کد

```bash
npm install
npm run dev              # مرورگر، http://localhost:3210
npm run desktop          # پنجرهٔ Electron روی سرور توسعه
npm run desktop:preview  # خروجی ایستا داخل Electron
npm run desktop:build    # ساخت نصب‌کننده و zip ویندوز در release/dist
```

موتور (پوشهٔ `backend/`) را برنامهٔ دسکتاپ خودش بالا می‌آورد، پس اول محیطش را بسازید. توضیحات کامل در [backend/README.md](backend/README.md) است:

```bash
cd backend
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
```

برای کار در مرورگر (`npm run dev`) موتور را جدا اجرا کنید: `.venv\Scripts\python -m server` (نشانی `http://127.0.0.1:8765`).

`npm run desktop:build` موتور را با PyInstaller به یک فایل اجرایی تبدیل می‌کند و داخل نصب‌کننده می‌گذارد (`pip install pyinstaller` لازم است).
