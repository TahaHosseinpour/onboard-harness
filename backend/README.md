# بک‌اند Onboard Harness

دو بخش جدا از هم:

| پوشه | کارش | به چه چیزی وابسته است |
|---|---|---|
| `harness/` | **بخش ایجنتیک.** ساختن و اجرای ایجنت با deepagents. | deepagents، LangChain، LangGraph |
| `server/` | **API محلی.** یک لایهٔ نازک HTTP روی `harness`. | FastAPI |

`harness` هیچ‌چیز از HTTP نمی‌داند و `server` هیچ منطق ایجنتی ندارد. تست‌ها هم مثل API فقط یک «صدازننده» از `harness` هستند.

## اجرا

```bash
cd backend
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
.venv\Scripts\python -m pytest        # مجموعه‌تست ثابت
.venv\Scripts\python -m server --dev  # API روی http://127.0.0.1:8765، برای کار روی رابط در مرورگر
```

`python -m server --selfcheck` (یا `harness-server.exe --selfcheck` روی نسخهٔ بسته‌بندی‌شده) همهٔ ابزارهای فایل و مرورگر را یک بار روی فایل‌های موقت امتحان می‌کند و می‌گوید کدام کار می‌کند؛ بعد از هر بیلد اجرایش کنید.

بدون `--dev` موتور فقط وقتی بالا می‌آید که `HARNESS_TOKEN` تنظیم شده باشد؛ برنامهٔ دسکتاپ در هر اجرا یک رمز تازه می‌سازد و خودش آن را می‌دهد.

مدل `demo://` بدون کلید کار می‌کند و یک کار کامل را قدم‌به‌قدم بازپخش می‌کند؛ برای دیدن جریان و برای تست‌ها.

## نقشهٔ `harness/` — از کجا شروع کنیم

از **`core.py`** شروع کنید. یک تابع دارد (`build_agent`) که ایجنت را با `create_deep_agent` سرهم می‌کند، و هر آرگومانش از ماژولی می‌آید که صاحب همان موضوع است. بقیهٔ فایل‌ها هر کدام یک مفهوم‌اند:

| مفهوم | فایل | چه می‌کند |
|---|---|---|
| حلقهٔ اجرا | `runner.py` | شروع، ادامه و توقف کار؛ تبدیل خروجی به رویداد |
| سقف تلاش، زمان، هزینه و دلیل توقف | `hooks/limits.py`، `tracker.py` | قبل از هر فراخوانی مدل چک می‌شود |
| پرامپت سیستم | `prompts.py` | بخش ثابت (`SYSTEM_PROMPT`) جدا از اطلاعات متغیر (`run_context`) |
| ابزارها | `tools/` | حساب دقیق؛ Excel/CSV؛ Word، PowerPoint و PDF؛ فایل فشرده؛ دیدن یک صفحهٔ وب. هر ابزاری که فایل عوض می‌کند باید در `permissions.WRITE_TOOLS` باشد |
| مدیریت Context | خودِ deepagents | نتایج بزرگ به فایل می‌روند، گفتگوی طولانی خلاصه می‌شود |
| برنامه و وظایف | `core.py` (`TodoListMiddleware`) | برنامه در state و در `plan.json` هر اجرا |
| مجوزها | `permissions.py`، `hooks/permission.py` | مجاز / با تأیید / ممنوع از `rules.yaml` |
| محیط اجرا و فضای کاری | `sandbox.py`، `workspace.py` | فایل‌ها محدود به پوشهٔ فضای کاری؛ شل با محافظ |
| بررسی صحت | `hooks/verify.py` | Sensorها و Stop Hook؛ Rubric اختیاری |
| حافظه | `memory.py` | فایل `AGENTS.md`، همیشه بار می‌شود |
| مهارت‌ها | `skills.py` | `SKILL.md`، فقط وقتی لازم شد خوانده می‌شود |
| قلاب‌ها | `hooks/` | هر فایل یک تضمین در یک نقطهٔ مشخص حلقه |
| چندایجنتی | `subagents.py` | پروفایل ایجنت‌ها و سپردن کار مستقل |
| پایداری | `durability.py`، `hooks/breaker.py` | Checkpoint، ادامه، Retry، مدل جایگزین، قطع‌کن |
| کنترل انسانی | `runner.py` (`resume`) | تأیید، ویرایش یا رد اقدامِ متوقف‌شده |
| مشاهده‌پذیری | `observability.py`، `events.py` | هر گام در `trace.jsonl` |
| هزینه | `hooks/cost.py` | شمارش توکن و هزینه از گزارش خودِ مدل |
| مدل‌ها | `models.py` | هر Base URL و کلیدی که کاربر تعریف کرده |

## فضای کاری روی دیسک

هر فضای کاری یک پوشه است و همه‌چیز همان‌جاست:

```
<workspace>/
  ...فایل‌های کاربر
  .harness/
    agents/      هر ایجنت یک فایل YAML
    skills/      هر مهارت یک پوشه با SKILL.md
    memory/      AGENTS.md
    rules.yaml   مجوزها
    runs/        برای هر کار: trace.jsonl، run.json، plan.json
    artifacts/   نتایج بزرگ ابزارها
    state.db     checkpointها (SQLite)
```

## چیزهایی که باید بدانید

- **ایزوله‌سازی شل سبک است، نه واقعی.** فرمان‌ها در پوشهٔ فضای کاری، با محیط بدون کلید، با مهلت زمانی و با فهرست فرمان‌های ممنوع اجرا می‌شوند؛ ولی اسکریپتی که ایجنت بنویسد هنوز می‌تواند هر فایلی را که کاربر می‌تواند باز کند. برای همین `execute` به‌طور پیش‌فرض «با تأیید» است. برای ایزوله‌سازی واقعی، `GuardedShellBackend` را با یک بک‌اند کانتینری عوض کنید.
- **پارامتر `permissions` خودِ deepagents استفاده نشده**، چون در نسخهٔ 0.7 با بک‌اندی که شل دارد کار نمی‌کند. تصمیم مجوز در `permissions.py` گرفته می‌شود و برای فایل و شل یکی است.
- **کلیدهای API** در مخزن امن سیستم‌عامل‌اند (`server/keychain.py`)، نه در پوشهٔ فضای کاری.
- **برنامه تک‌کاربره است.** حساب کاربری، نقش و اشتراک‌گذاری وجود ندارد؛ هر کس به این سیستم و این پوشه دسترسی دارد، همان کاربر است.
- **API فقط برای خودِ برنامه است** (`server/app.py`): فقط روی `127.0.0.1`، با رمز در هدر `Authorization`، و با ردِ هر درخواستی که `Host` یا `Origin` آن مال برنامه نباشد. اگر مبدأ تازه‌ای لازم شد (مثلاً پورت دیگری برای سرور توسعه)، به `_ORIGINS` اضافه‌اش کنید.
- **قوانینِ خراب یا گم‌شده یعنی «محتاط»، نه «آزاد».** `load_rules` برای فایل گم‌شده پیش‌فرض‌ها را برمی‌گرداند و برای فایل خراب خطا می‌دهد؛ ایجنت هم هیچ‌وقت بدون تأیید کاربر `rules.yaml` را عوض نمی‌کند.
- **اجرای زمان‌بندی‌شده وجود ندارد.**
